DATA STRUCTURES
===============

ConfigMap
- Metadata (name, namespace, uid, timestamps)
- Key-value data (100 items max)
- Resource versioning

Secret  
- Metadata (name, namespace, uid, timestamps)
- Secret type (Opaque, basic-auth, etc.)
- Encrypted key-value data (100 items max)

PersistentVolume
- Metadata (cluster-scoped, no namespace)
- Spec: storage class, capacity, access modes, type, path
- Status: AVAILABLE, BOUND, RELEASED, FAILED
- Claim reference for binding tracking

PersistentVolumeClaim
- Metadata (namespace-scoped)
- Spec: access modes, storage request, storage class
- Status: phase (AVAILABLE/BOUND/RELEASED), volume name

StatefulSet
- Metadata (namespace-scoped)
- Spec: replicas, service name (for headless service), labels
- Status: ready replicas, updated replicas

CURRENT LIMITATIONS
===================

1. Storage Binding
   - No dynamic provisioning
   - Greedy algorithm (not optimal)
   - No quota enforcement

2. StatefulSet
   - No cascading deletion
   - No ordinal-based pod deletion
   - No persistent identity for network

3. General
   - In-memory storage (no persistence to etcd)
   - No quota management
   - No automatic garbage collection
   - No backup/snapshot support
